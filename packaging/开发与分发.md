# 开发与分发

完成影响 EitHost 程序、运行配置或构建/打包流程的修改并通过相关验证后，双击项目根目录的 `package.cmd`，或在 Windows PowerShell 中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-eithost.ps1
```

纯文档、注释或 agent 指令修改按其影响检查即可。无参数 `scripts/publish-eithost.ps1` 也进入同一发布流程。版本自动读取 `src/EitHost.App/EitHost.App.csproj`，不要沿用旧命令中的固定版本号。

唯一运行目录是 `release/EitHost-Windows-x64`，运行 `EitHost.App.exe`。默认命令从当前已保存源码构建并替换这个目录的程序，包括尚未提交的修改。保留原 `Data` 和用户配置，不额外生成 `dist`、日期目录或归档包。详细完成要求见 [发布规则](RELEASE-RULES.md)。

目录分工：

| 目录 | 用途 |
|---|---|
| `src` | 开发源码 |
| `release/EitHost-Windows-x64` | 本机正式运行软件及其 `Data` |
| 用户明确指定的归档目录 | 仅在用户要求对外分发时使用；不是日常运行入口 |
| 系统临时目录 `EitHost.Package.*` | 发布中间文件、临时 obj/bin、验证文件；退出时清理 |

完整 .NET/WPF 与所有应用功能保留，关闭调试符号和应用 ReadyToRun，禁止代码裁剪。外部 HDF5 与 USB2070 文件保持原有位置；压缩仅改变存储方式。接收方的配置和数据由接收方创建或保留。

默认发布只更新唯一日常目录，构建和 HDF5 包级检查先在临时目录完成，通过后事务替换程序并校验数据保留，再检查安装后版本和 HDF5。

接收方运行包不依赖源码目录、Git、SDK 或开发机的本机路径；USB2070 驱动和兼容的 PyEIDORS 后端仍使用接收方已配置的环境。

只有用户明确要求对外分发时，才指定一个新的空目录，例如：

```powershell
.\scripts\package-eithost.ps1 -OutputDirectory 'D:\Transfer\EitHost-package' -ZipOnly
```

显式归档模式生成 ZIP；可用 7-Zip 时还支持 7z。该模式不包含本机实验数据或个人配置，也不改变日常运行入口。

`VERSION.json` 记录版本、源码提交及实际构建输入哈希；`SHA256SUMS.txt` 校验程序文件；`release/publish-manifest.json` 记录最近一次更新和数据保留结果。Git 用于历史管理，不自动提交或推送。
